# 证据、独立性与复用

细化 [协作约定](workflow.md)「真实证据与增量复用」。字段是**表达方式**，不替代原文判据：缺字段时按中文如实说明，不因缺字段改判结论。

## 正交状态

分开记录，不合并为单一状态值：「未运行」与「失败」、「模拟通过」与「真实通过」不能互相替代。

| 字段 | 取值 | 说明 |
|---|---|---|
| `execution_status` | `completed｜not_run｜interrupted｜timed_out｜unknown` | 这一步是否真的执行完 |
| `outcome` | `passed｜failed｜inconclusive` | 执行完之后的结论 |
| `evidence_mode` | `actual｜simulated` | 证据来自真实执行还是模拟 |
| `freshness` | `current｜stale｜unknown` | 证据是否对应当前产物与环境 |

失败另记相对基线的归属：`baseline_relation: new｜preexisting｜unknown`；保留宿主原始错误，不自造固定错误码集。

## 证据要素与版本绑定

- 每条证据绑定：受测版本或被审文件、实际命令、cwd、退出码、输出/截图位置，以及影响结果的环境信息（见 [环境与版本](environment-version.md)）。
- 证据绑定被审**产物版本**：新构建与被测运行版本分列，不把新产物当作旧运行的证明，也不把旧运行的通过算到新产物上。
- 文档齐全、格式正确或代码编译通过不等于业务验收通过；测试数量不代替行为覆盖。

## 独立性

- 独立性记 `independence: self｜independent｜mixed｜unknown`，并写明审查者、输入与隔离依据（谁审、看过什么、是否接触过被审内容的作者过程）。
- 同一 Agent 的自我审查记为 `self`；改换角色名不产生独立性。
- 字段值不证明独立性：据实际过程判断，依据不足写 `unknown`，不把缺失的独立审查改称自审通过。

## 复用与失效

- 当前相关输入、方法与环境未变时复用已有证据；变化后补受影响检查，只补受影响的部分。
- 基线变化、验收变化或环境变化使旧证据失效：失效的证据保留为历史、不作为现行结论，并**重新核验**；问题状态保留，未解决项不因证据失效而撤销或丢失。
- 只在问题已关闭，或现有修复交接被明确取代时，才撤销旧的修复交接；历史发现始终保留。
- 复用要说明复用的是哪次证据、对应哪个版本与范围；无法确认对应关系时重新取得证据。
- 重开已关闭的问题须有当前反例；旧缺陷不自动升为新需求。

## 三级完成层级

- **研发完成**：当前实现满足验收，必要检查与适用审查有依据，阻断问题已处理。
- **发布就绪**：研发结果之外，候选版本、目标环境、配置、恢复准备与必要授权已核对成立，未实际部署。
- **上线验证**：存在真实部署事实，并完成约定的健康与业务观测。
- 三级要求的是**不同判据**，不是互斥状态：给出发布就绪结论不要求已部署；上线验证依据真实部署与约定观测，不要求必须实际执行恢复操作（恢复路径的准备与核对属发布就绪）。
- 报告写清本次达到哪一级、还缺什么；只要求准备时止于准备，不把准备写成已部署。
