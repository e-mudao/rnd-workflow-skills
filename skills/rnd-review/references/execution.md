# 执行、日志与无进展处理

细化 [协作约定](workflow.md) 的「分批与上下文」「真实证据与增量复用」「授权与阻断」；执行状态、结果与证据方式的分开表达见 [证据与复用](evidence.md)。

## 读取与截断

- 先读索引、入口或目录，再读相关输入；能定位到章节、函数或字段时不通读整份文件。
- 输出过长或工具截断时，分段读取，或把完整输出落到文件后按需引用关键行；记录落盘路径与截断位置，不用截断片段下结论。
- 当前会话已加载且未变的共同约定与方法可复用；版本变化或上下文丢失后按需重读。

## 编辑与并发保护

- 写入前重读目标当前内容，保留用户修改与已有并发编辑；已有并发编辑时先重读再整合，冲突时保留用户内容并说明归属。
- 范围保持最小：不重构无关部分，不代改验收；未经授权不得覆盖正在被验收或运行的候选，也不覆盖用户修改。
- Patch 或差异不适用时先重读并重新定位，不强行套用旧差异；修改后检查实际 diff，确认改动即所要的改动、且没有附带改动。
- 临时副本或副本目录用于调查与测试；用户明确要求的恢复操作按该请求执行，不以此为名做未授权的覆盖（见 [环境与版本](environment-version.md)）。

## 运行与失败反馈

- 每次执行记录：实际命令、cwd、退出码、输出或截图位置、受测版本；退出码取宿主进程状态，不从日志文本推断（管道、包装脚本与并发写入都会改掉它）。
- 新的失败不能被旧成功盖过；非零退出保留为失败；缺项、未运行、中断、模拟与自审分别说明，不并列成同一次通过。
- 保留失败的类别与范围（编译失败、行为断言失败、环境失败、权限失败）；宿主原始错误保留原样，不自造闭集错误码；相对基线的归属用 `baseline_relation: new｜preexisting｜unknown`，判断不了就写 `unknown`。
- 超时或结束状态未知：先调查实际状态（进程、回执、产物、日志尾部），再决定是否重放；结果未知不得盲目重放。

## 日志与输出

- 完整日志留在文件，只带当前需要的结果与关键行；给位置与检索方式，不倾倒全文。
- 保留失败输出的首尾与断言/错误行，足以复现与对比；被截断时说明截断位置与已知范围。
- 分次、增量或流水式输出归属同一次执行，注明各段顺序与时间；不把两次运行的输出拼成一次通过。

## 无进展处理

- 无进展按**同一输入、同一操作、同一失败且无新信息**判断；有新证据的尝试（新的观察、换输入或换路径取得的新结果、范围收窄后仍可推进的部分）不算无进展——不自动停止，也不按失败次数上报用户。
- 确认无进展时停止重复尝试，重新检查假设与架构，并带证据上报：已试路径、观察到的反例、当前未知、可继续的替代工作或需用户决定的选择。
- 权限或外部前置条件被拒时，说明依赖与未完成范围，可使用宿主的正规审批流程请求授权；禁止绕过——不绕行、不改称已执行，也不把缺失的独立审查改称自审通过。
- 无进展不是失败结论：按已取得的实际结果与未解决项交付，保留可接续的当前位置。
