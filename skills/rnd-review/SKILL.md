# 审查当前事实

执行前读取 [协作约定](references/workflow.md)，确定本次范围及阶段返回方式。按需读取 [执行与日志](references/execution.md)、[证据与复用](references/evidence.md)。

先确定请求的被审产物、范围与版本，再选择相关权威输入。负责审查记录，不修改被审内容；规格/计划审查无需尚不存在的代码、diff 或执行输出。

## 方法

1. 按产物选择检查：需求/盘点查来源、遗漏、范围和事实/推断；规格/设计查行为、可测试性、一致性与兼容；计划查覆盖、真实接口/依赖、切片、证明和停止点；实现查正确性、边界、兼容、风险和测试；实验/分析查输入、方法、样本、可重复性及结论是否符合证据。使用适用领域方法，不把编译或脚本成功当质量证明。
2. 对禁用/隐藏/拒绝检查解除条件和合法恢复：单例能否满足前置条件、模态取消后同一实例能否重复操作；不能靠去掉安全检查或只看重启正常来关闭问题。验证质量要说明测试捕获哪个旧错误；缺类型的编译 RED 可建立新接口，但不证明行为回归，测试数量不代替风险覆盖。
3. 每条发现给出文件定位、触发条件、实际影响、严重度、建议和责任作者。缺上下文或未检查的范围明确列出。
4. 先依据原始文件形成判断，再参考实施者解释。同会话自审明确标记为非独立；真正独立审查须说明审查者、输入和上下文隔离依据。只有需要且获授权时才委派。
5. 在项目现有审查记录或任务章节保存范围、被审版本、发现、未解决项。作者修复后复验具体问题，保留前后结果。

## 核验与返回

检查三件事：REV-1 输入与当前被审产物及版本一致；REV-2 所需独立性有事实依据；REV-3 完整目标内的发现已处理并具体复验。只审查请求允许发现未修复，记录实际状态和建议，不因缺修复而扩大请求。

复验前核对当前被审版本，按报告/版本定位发现；关闭后同步撤销当前修复交接，保留历史结果。未运行检查不能写成全部通过。

完整目标内，返回报告位置、实际发现、未关闭项及下一动作给 lead，按协作约定交责任作者修复后回本角色复验，再接续 verify。样本/方法交 plan，结论交 discover，脚本/执行事实交 build；review 不能自行改被审分析。直接审查只交付发现、责任作者及复验建议，不修复或重跑被审实验。

请求明显超出本角色范围时，保留当前目标、授权、停止点和已知结果，转入 `rnd-lead` 接续；已由 lead 分派的工作按既有阶段返回约定接续。转入前按协作约定核对目标技能可用性。同一 Agent 切换职责，无需用户重新调用。

方法改编自 Superpowers 和 agent-skills 的需求符合性、质量、测试审查与按影响分级，见 [固定来源](references/methods.md)。
