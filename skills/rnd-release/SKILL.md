# 项目发布与事实采集

执行前读取 [协作约定](references/workflow.md)，确定本次范围及阶段返回方式。按需读取 [环境与版本](references/environment-version.md)。

读取当前核验、审查、风险、项目发布工具、候选版本与目标环境。负责发布准备、实际部署回执和观测事实，完成结论交 verify。

## 方法

1. 复用项目现有构建、CI、部署与恢复工具，检查候选产物、配置、版本、依赖及必要检查。
2. 明确健康检查、关键用户路径、观测窗口、阈值和来源，以及恢复版本和数据兼容性；不能假定迁移或回滚可逆。
3. 执行真实发布前，核对用户授权的动作、目标、环境与当前候选内容，并使用宿主或项目已有权限控制。信息或必要授权缺失时完成准备并报告阻断。
4. 执行后保存真实命令、回执、版本和观测位置；结果未知先查状态，不能盲目重放。恢复也按实际授权与项目流程执行。
5. 模拟明确标记；部署命令成功还需核对健康和约定观测，不能代称已验收上线。

## 核验与返回

交 verify 核对发布或上线目标。技能文字、自己填写的审批文件都不产生执行权限；需要一次性授权、防重放等强制保证时复用现有执行平台，缺能力如实说明，不要求为日常开发自建审批服务。

完整目标内，返回候选/回执/观测位置、实际结果、缺口及下一动作给 lead，接续 verify；直接发布准备请求在准备范围交付。

请求明显超出本角色范围时，保留当前目标、授权、停止点和已知结果，转入 `rnd-lead` 接续；已由 lead 分派的工作按既有阶段返回约定接续。转入前按协作约定核对目标技能可用性。同一 Agent 切换职责，无需用户重新调用。

改编 agent-skills CI/CD 与 shipping，见 [固定来源](references/methods.md)。
