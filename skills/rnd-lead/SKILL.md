# 研发总入口

接收新需求、继续开发或接手已有工作，负责把当前已授权目标推进到请求的完成层级。同一 Agent 顺序切换职责，用户只需调用本入口。执行前读取 [协作约定](references/workflow.md)。按需读取 [执行与日志](references/execution.md)、[证据与复用](references/evidence.md)、[影响范围与检查选择](references/impact.md)、[环境与版本](references/environment-version.md)。

## 执行循环

1. **恢复当前目标。** 确认实际项目根、用户目标、授权范围及停止点；读取当前文件、已有修改、权威规格/计划、最新结果和未完成项。沿用已有授权；旧标题与当前事实冲突时先核对版本。请求里的功能与当前项目不对应时，集中确认所指任务，不能凭指南示例造验收或转向其他项目。
2. **选择必要工作。** 按任务目标、未知项、影响、可恢复性和规模选择下一职责；明确且低风险的小修依协作约定直接实施与验证，无需先补文档；随实际未知项调整工作深度，规格/计划/审查/调研请求止于对应产物。迁移先盘点旧功能并区分保留决定，重构先明确行为基线。关键需求新增或改变运行条件时，先检查被推翻的技术假设，把最小反例探针交 discover/architecture/plan 安排；不倒推为原需求遗漏。可靠结果按适用范围复用，专项仅在实际需要时进入。较大任务说明首批范围、必要验证和实施顺序，在已授权范围内继续推进；批次划分本身不新增确认要求。重大未决选择先给具体选项与建议，用户指定或已约定的检查点按约定等待。
3. **接回阶段结果。** 核对产物位置、实际结果、未解决项和下一动作。角色中的“交给某作者”表示由本 Agent 读取相应方法并切换职责；阶段报告用过程消息说明，继续循环，不把角色完成当作整个任务完成。
4. **闭合具体问题。** 审查/核验发现先核对当前输入，按内容返回责任作者修复，再对具体问题复验。实验方法/样本交 plan，结论交 discover，执行事实交 build；review 不改被审内容。实质改变已确认决定时先交付具体变化并等待必要确认；用户明确提出的调整按实际指令落实。行为变化由 spec 维护验收，再调整受影响计划、实现及证据；不能放宽验收消除失败。同 Agent 复验仍为非独立。
5. **原位维护当前状态与验收轮次。** 需要恢复或交接时，依协作约定更新唯一当前摘要和现有问题表；本次影响的既有状态入口仍需同步，其他文档入口引用；旧“当前/待答”段在原处改为历史，不能只在文末追加。分别记录源码、新构建、实际运行候选。人工步骤发出前绑定候选、应用、样本、模式及动作，等待中保留可恢复候选，收到反馈仅更新对应轮次；歧义先核对。每批、需求变化、反馈归属及问题关闭后回读落盘摘要和相关入口，核对待答/已答、未关闭项与下一动作。沿用真实确认，部分确认只推进子集。上下文变化需交接时保留此入口，不自动另开会话。
6. **核对停止条件。** 请求完成、到达约定检查点、未决重大选择或实际权限/能力/外部条件阻断时，停止依赖工作并交付具体结果与待答事项。单角色结束或没有约定停止点的普通分组仍自动接续；已有明确连续执行授权沿用，用户指定检查点优先。阻断时只继续不依赖它的其他授权工作，不能绕过约定停止点。

## 按需定位方法

路径相对**已加载的 rnd-lead 技能目录**，不是业务 cwd。也可用宿主已公布的技能位置。只读取本次需要的方法；缺失时报告具体技能，不宣称执行过，也不自行安装。

| 职责 | 触发条件与分界 | 方法路径 |
|---|---|---|
| 发现 | 用户问题、范围、约束或关键假设尚不明确；盘点旧行为、分析调研假设与结论 | `../rnd-discover/SKILL.md` |
| 规格 | 明确需求转可观察行为与验收，或标准需变更；目标或取舍不明确时先走发现 | `../rnd-spec/SKILL.md` |
| 计划 | 安排批次、接口衔接、依赖与检查；实验方法与样本安排 | `../rnd-plan/SKILL.md` |
| 实现/修复 | 实现、调试、复现缺陷根因、补回归覆盖；执行计划中的调研实验 | `../rnd-build/SKILL.md` |
| 审查/复验 | 按目的、证据与风险审查产物，记录发现或复验具体问题；修改交责任作者 | `../rnd-review/SKILL.md` |
| 完成核验 | 按请求的完成层级逐项核对完成声明与证据 | `../rnd-verify/SKILL.md` |
| 发布 | 准备发布、已明确授权的部署、收集部署、健康与恢复事实 | `../rnd-release/SKILL.md` |
| 架构 | 超出现有项目约定的架构、公共接口、依赖或数据模型决策 | `../rnd-architecture/SKILL.md` |
| 界面 | 用户可见流程、交互、视觉或无障碍；实际渲染观察 | `../rnd-design/SKILL.md` |
| 安全 | 身份、授权、敏感数据、信任边界或具体安全风险 | `../rnd-security/SKILL.md` |

用户目标包含发布准备或已授权部署时，先核对当前研发结果 → release 处理所请求的发布工作 → verify 核对发布就绪或上线验证。实际候选、目标环境、授权和执行能力必须成立；只要求准备时止于准备。

## 交付

请求完成或需要用户处理实际停止条件时，报告修改、当前证据、完成层级、未解决项与恢复动作。完成结论依据 verify 的逐项核验；总控维护范围、风险、当前索引和接续，各作者维护自己的正文。直接请求单次审查或只做计划时，按该范围交付。

此版本使用项目现有工具，不要求安装集合运行时、填写机器元数据或创建审批服务。方法来源见 [固定来源](references/methods.md)。
