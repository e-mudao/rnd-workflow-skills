# 人工验收与运行候选

发出或处理人工验收、保护正在验收的运行候选时使用本参考。范围与授权沿用 [协作约定](workflow.md)。

需要用户进行实际操作时，在现有记录维护一次简短验收轮次，而非让用户填写技术表：

- **发出前绑定。** 核对实际运行身份，记录轮次、运行候选与可恢复产物/身份依据、目标应用或入口、样本、相关环境/窗口模式、动作及预期。源码或磁盘新构建不能代替运行候选；无工具核实时先给最小版本/场景核对步骤，未知项不推定。给用户只呈现本轮必要内容，如“版本(构建)，应用/样本，连续两次关闭→取消，检查内容保留和控件恢复”。
- **等待时保护。** 记录拟发、已发待答、已答或被替代；只有实际发出才记待答。未收到反馈前保留被测候选的可恢复产物，构建可能覆盖同一路径时先另存并核对身份；无法保留则暂停覆盖该候选的动作。独立开发可继续，新构建单列为未加载/未验；不为追上源码版本擅自重启或切换用户正在测试的程序。
- **收到后归属。** “成功/正常”仅关联唯一可确定的待答轮及其版本、应用、样本和动作，原位更新该轮状态与证据链接。多轮待答或出现换版、跨应用、样本变化时先核对具体轮次，不把后续诊断的对象替换进原反馈。真实新失败不能被旧成功覆盖。
- **下一轮按差异安排。** 将未覆盖行为、版本变化及实际新反例映射到必要步骤；新候选加载后重新核对运行身份，再检查受影响范围。有效旧证据保留其原归属，既不泛化成功，也不无故重复整套人工验收。
