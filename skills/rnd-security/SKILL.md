# 按实际风险检查安全

执行前读取 [协作约定](references/workflow.md)，确定本次范围及阶段返回方式。按需读取 [影响范围与检查选择](references/impact.md)。

读取真实变更、需求、资产和信任边界。负责有范围与覆盖依据的聚焦安全审查；完整审计只在任务明确需要时开展。

## 方法

1. 明确入口、数据流、身份、授权点、敏感数据和适用攻击类别，列出覆盖单位与未覆盖项。源码检查默认只读。
2. 跟踪具体数据与授权路径，记录根因候选、触发前提、定位和影响；区分已证实、需验证、排除及范围外。
3. 执行不可信目标代码或攻击复现前，核对已有 OS 强制隔离同时满足：
   - 禁止外网，本地通信仅使用隔离回环。
   - 从空环境填入安全变量白名单；HOME、临时目录和缓存位于独立 scratch，不继承真实凭证。
   - 目标与工具链只读，目标进程仅能写独立 scratch；构建需要就地写入时，由 Agent 在 scratch 内准备一次性源码副本。
   - 明确 CPU、内存、进程数、文件大小、磁盘与运行时间上限。
   使用假身份和假秘密，不访问生产或共享外部端点。任一条件不能确认或落实时，不执行目标代码，继续只读源码审查并记录需验证项；沿用现有能力处理。
4. 核对当前源与旧证据，输入及环境没变时可引用已有覆盖；受变更影响处重新验证。零发现须有覆盖和方法依据。
5. 在项目安全记录或任务章节保存范围、覆盖、发现、需验证项及复验；风险交 spec/plan，已证实问题交责任作者修复。

## 核验与返回

安全覆盖与复验缺口由本角色处理（RTN-7）；候选未经验证不能写成已确认漏洞。高风险所需独立核验缺失时如实报告阻断。

完整开发目标内，返回覆盖/发现位置、实际结果、需验证项及下一动作给 lead，接续责任作者或核验；直接安全审查请求按该范围交付。

请求明显超出本角色范围时，保留当前目标、授权、停止点和已知结果，转入 `rnd-lead` 接续；已由 lead 分派的工作按既有阶段返回约定接续。转入前按协作约定核对目标技能可用性。同一 Agent 切换职责，无需用户重新调用。

改编 security-audit-skill 的聚焦模式、覆盖、候选复验与执行隔离，见 [固定来源](references/methods.md)。
