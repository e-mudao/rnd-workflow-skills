# 协作与证据约定

按需求规模使用项目现有文件。目标明确、影响局部且容易恢复的任务，可直接依据用户请求与相关现有事实实施，以修改和必要验证交付，不为满足角色输入补造简报、规格、验收编号或计划。需要记录的小任务可共用一份 Markdown；已有足够记录就直接引用。没有集合 JSON、固定目录或摘要服务前提。内容按职责只维护一处正文：spec 写行为与验收，plan 引用验收 ID/章节并写实施和证明，verify 写证据与结论，lead 写状态和入口。跨文档使用相对链接与稳定 ID；需要参数时引用其权威位置，不复制完整条件和数值另成一版。普通修复在已有章节闭环；只有实际行为决定变化才更新规格。

## 按目标选择工作

先看目标、未知项、影响、可恢复性和规模，再选择必要职责；技术类型主要决定证明方式。明确小修不强制完整 PRD/计划；权限、数据删除或公共接口等改动仍按实际影响检查，不能仅凭 diff 小判为低风险。只有文档请求止于文档。迁移/重开发先区分旧事实与决定保留、改造、舍弃的需求；旧缺陷不自动升为新需求。保持行为的重构先明确基线与接口。调研围绕问题/假设组织方法、执行和分析，不预设必须有正面结果或产品实现。使用项目已有工具、领域方法与专项技能，不宣称通用流程覆盖全部专业核验。

澄清和规划只解决当前阻碍推进的未知项：先查相关代码、文档与既有决定，信息足以支持下一步就推进；发现具体依赖、重要取舍或较高恢复成本时再深化。调查消除复杂性后，缩减尚未执行的安排，在原处更新过时计划并保留必要决定；实质改变已确认决定仍遵守人工检查点。已有适用计划按计划实施，用户明确要求的文档和项目强制要求仍需交付。流程简化不减免与影响相称的验证、授权及证据要求。

## 阶段返回与范围

由 lead 在完整开发目标内调用时，每个角色返回四项：**产物位置、实际结果、未解决项、建议下一动作**。这是交回当前 Agent 的总控职责，由其读取下一方法并执行；用过程消息交代进展，不因“交 spec/plan/build”等文字就结束任务或要求用户再次调用。返回内容放在已有记录或过程消息中，无需新建交接文件。

直接调用单角色按本次请求交付；若已有完整目标仍有效，按该目标和实际检查点接续。用户明确“只审查”“计划完成后停止”等限制时，以该限制为准。职责切换保留作者归属，不意味着另一个人或独立审查，也不扩大授权。

切换到其他技能前，确认其正文可通过宿主提供的位置或已知安装路径读取；本会话已加载且未变化的正文可复用。目标技能不可用时，明确说明缺失技能及受影响步骤，不得声称已加载或执行该技能，也不自行安装。继续当前角色内可独立完成的已授权工作，保留其余交接事项。角色名称和切换本身不产生授权。

## 人工检查点

- 较大任务首次进入时，lead 说明目标、首个可验收范围、必要审查及实施顺序，在已授权范围内继续推进。首次进入或分批本身不构成待答事项；建议检查点只有经用户约定后才成为停止点。重大未决选择按下条处理。
- 已有明确批次/检查点或连续执行授权直接沿用，用户指定停止点优先。确认后 lead 自动选择技能接续；普通职责切换和没有约定停止点的任务分组无需另批。
- 未决重大行为、功能取舍、公共接口或恢复成本明显的选择，先完成可独立调查，交付具体选项与建议再取得必要决定。到达约定批次边界时报告产物版本/范围、实际结果、问题及建议下一批，等待答复；沉默、时间经过、文档齐全和 review 通过都不替代确认。
- 确认绑定所说明的版本、内容和范围；部分确认只推进子集，其余保持待答。Agent 提议实质改变已确认决定时，先交付变更、影响与建议，取得必要确认后执行依赖该变化的工作。用户明确提出的调整按实际指令落实，含糊处澄清；普通授权内修复/复验和排版不重复询问。

## 真实证据与增量复用

记录实际版本或被测文件、命令、cwd、退出码、输出/截图位置和影响结果的环境信息（工具版本、相关配置/数据、目标环境）。未知项直接说明。文档合并时说明引用哪个章节；需要精确校验时用项目现有摘要工具计算对应字节，不编造摘要。

核验先绑定当前项目和权威验收；提示词中的示例功能与之不符时，集中澄清所指任务，不造验收、不自行改成另一项目或功能。无实际交接需要时一句澄清即可。

当前相关输入、方法和环境未变时复用已有证据；变化后补受影响检查。新的失败不能被旧成功盖过；缺项、中断、未运行、模拟、自审要如实区分。文档齐全、格式正确或代码编译不等于业务验收通过。

## 分批与上下文

批次围绕可独立检查的功能结果，不按技能、文件或固定任务数机械拆分。先读索引/目录/入口，再读相关输入；当前会话已加载且未变的共同约定、方法与来源可复用，版本变化或上下文丢失后按需恢复。完整日志留在文件，只带当前需要的结果。每批更新现有索引；下一批上下文不同、恢复困难或用户希望时准备简短交接并建议换会话，不自动另开任务、不假造剩余 token 门槛。人工检查点、职责切换和会话切换分别安排。

## 授权与阻断

沿用已授权范围，按上文处理未决重要选择及明确约定的停止点，不因普通方法切换重新授权。实际缺失技能、独立审查、工具、权限或外部前置条件时说明依赖和未完成范围，只继续不依赖该条件的其他授权工作，不能绕过约定停止点。

技能文本不产生执行权限。发布、发消息和不可逆操作使用宿主/项目实际授权；结果未知先调查，不能盲目重放。
