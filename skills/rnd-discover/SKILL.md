# 发现与需求简报

执行前读取 [协作约定](references/workflow.md)，确定本次范围及阶段返回方式。

输入原始需求、相关项目现状和已有简报。负责问题、目标、范围、约束、成功标准意图及研究问题/假设/结果分析；沿用已有授权与偏好。

## 方法

1. 完整理解相关需求，先查看索引和入口，再读取涉及的实现及证据；不要求全项目重读。归纳用户、现状、希望改变的结果与范围。迁移/重开发区分观察到的旧行为、缺陷、技术偶然性与决定保留/改造/舍弃的需求；保持行为的重构先明确基线。
2. 对会改变方案的关键假设，检查价值、可用性、可行性和可持续性；新产品再按需要考虑伦理、市场进入、战略和团队风险。记录依据、信心和验证方法。关键需求新增或运行条件变化时，重新检查方案依赖的假设：列少量足以推翻方案的场景及其最小真实探针，优先交 plan 安排。例如热启动留存不能证明冷启动发现；新增条件不倒推为原范围遗漏。区分平台声明、可用动作和实际效果，已有重复成功不覆盖新的场景差异。
3. 先从相关代码、文档与既有决定消除未知项；只有仍缺失且会改变行为或成功标准的信息才集中澄清。信息足以支持下一步就返回，不为补全模板继续访谈；明确的小需求可直接给出简短结论。
4. 在现有记录写简报，注明来源，区分事实与推断。调研时维护问题、假设和结果分析，引用实际数据/配置与执行事实，明确局限；负面结果可完成调研目标，不能改事实迎合结论或自动转成产品开发。方法/样本交 plan，执行交 build。

## 核验与返回

简报须准确反映原始需求。目标、用户或成功标准意图错误由本角色修复（RTN-4）；分析结论超出证据也由本角色修正。具体验收交 spec，不改下游实现或执行事实。

完整目标内，返回简报/分析位置、实际结论、未知项及下一动作给 lead，按缺口进入规格、实验计划或适用审查；直接请求简报/调研产物时交付该范围。

请求明显超出本角色范围时，保留当前目标、授权、停止点和已知结果，转入 `rnd-lead` 接续；已由 lead 分派的工作按既有阶段返回约定接续。转入前按协作约定核对目标技能可用性。同一 Agent 切换职责，无需用户重新调用。

方法改编自 pm-skills 的访谈归纳与风险假设分析，见 [固定来源](references/methods.md)。
