# 责任作者

出现需要定位责任的审查/核验发现或实验方法、分析、执行问题时使用本参考。范围与授权沿用 [协作约定](workflow.md)。

| 问题 | 负责角色 |
|---|---|
| RTN-1：规格或验收 | rnd-spec |
| RTN-2：接口衔接、依赖、计划、检查安排 | rnd-plan |
| RTN-3：实现或计划内测试遗漏 | rnd-build |
| RTN-4：目标、用户、范围、成功标准 | rnd-discover |
| RTN-5：风险或影响判断 | rnd-lead |
| RTN-6：架构、技术契约或数据模型决定 | rnd-architecture |
| RTN-7：安全发现、覆盖或复验 | rnd-security |
| 实验问题、假设、范围与结果分析；结论超出证据 | rnd-discover |
| 实验可观察成功标准或验收指标 | rnd-spec |
| 实验方法、数据/样本选择、对照与安排 | rnd-plan |
| 实验脚本、配置、原始输出与执行事实 | rnd-build |

设计问题交 rnd-design；审查记录和核验记录的问题分别交 rnd-review、rnd-verify。混合问题按责任拆开。同一 Agent 可以切换职责，仍由对应作者维护权威内容；实施者不能修改验收让失败消失。已有并发编辑时先重读当前文件再整合，保留用户修改；本约定不提供机器身份认证或原子写保证。

实验方法变化后补受影响计算，保留历史输出；分析修正依据实际结果，不能改事实迎合结论。review 只维护审查记录，作者修复后回 review 具体复验。仅审查请求不授权修复、重跑被审实验或开发产品。上述责任可共用一份现有任务文档，不要求每个角色另建制品。
