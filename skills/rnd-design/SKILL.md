# 产品界面与交互设计

执行前读取 [协作约定](references/workflow.md)，确定本次范围及阶段返回方式。

输入用户问题、规格、现有界面/设计系统和目标设备。负责必要的交互、视觉决定及观察证据。

## 方法

1. 先查看实际页面或设计材料，明确用户任务、路径、状态和当前问题，沿用已选视觉与组件约定。
2. 先判断典型使用状态下用户任务能否完成，再检查布局算法是否符合约定。检查主路径及加载、空、错误、权限、成功状态，给出具体改进并核对内容层级、键盘/焦点、对比度和响应式。涉及原生桌面窗口、浮条或面板时，读取 [原生桌面检查](references/native-desktop.md)，推广前覆盖典型几何与模式；观察记录列出任务结果、隐藏原因的已证实/未核范围和证据类型。其他界面无需读取。
3. 检查请求只产出观察与建议，不修改页面实现。用户已授权实施时，按下一步落实必要决定，再由 build 实施有限改动，随后重新观察；同一 Agent 可以顺序切换职责。交互/布局/可访问性检查配合真实渲染和视觉审查，分别说明截图与操作证明的范围。
4. 已授权、行为明确且影响局部容易恢复的调整，可直接交 build 实施并重新观察，无需补造规格或计划。需要新增行为决定或改变验收时交 spec 更新当前依据；存在重要接口、依赖或实施顺序时交 plan 安排。已有适用规格、计划和项目强制要求仍须遵循。需要留存的决定与证据写入项目现有文档。

## 核验与返回

交 reviewer/verify 当前状态和真实截图/操作证据。缺浏览器或可视材料就说明未验证，不能以格式检查或代码编译证明视觉质量。

完整开发目标内，返回设计/观察证据位置、实际结果、缺口及下一动作给 lead，接续必要作者或审查/核验；直接检查请求只交付观察与建议。

请求明显超出本角色范围时，保留当前目标、授权、停止点和已知结果，转入 `rnd-lead` 接续；已由 lead 分派的工作按既有阶段返回约定接续。转入前按协作约定核对目标技能可用性。同一 Agent 切换职责，无需用户重新调用。

保留 HumanLayer design-control-loop 的观察反馈循环，见 [固定来源](references/methods.md)。
