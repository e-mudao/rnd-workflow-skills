# 环境、工作区保护与版本交付

细化 [协作约定](workflow.md) 的环境信息、授权与阻断部分；证据的时效与复用见 [证据与复用](evidence.md)。

## 环境核对

- 记录影响结果的环境信息：工具与解释器版本、相关配置与数据、目标环境、实际命令与 cwd。
- **工具链探测**：命令来源（项目脚本、包管理器、全局工具或宿主能力）、依赖安装状态与锁文件摘要、目标平台与设备差异。锁文件摘要只证明该文件未变，不证明环境未变；与解释器/工具版本、实际命令与 cwd 一并记录。
- 环境不明或无法确认时标 `freshness: unknown` 并说明可执行的替代检查，不假设环境一致。
- 何时重做探测：工具链、依赖或目标环境变化后；换会话、换机器或恢复上下文后；发布或部署前。命令选择与检查安排由 plan 归口，执行事实由 build 记录，两者都不替代这条探测要求。

## 工作区保护

- 不擅自替换用户正在验收或运行的实例：新构建与被测/运行版本分列，可能覆盖被测候选时先保存并核对可恢复产物。
- 写入前重读当前内容，保留用户修改与已有并发编辑；范围保持最小。
- 恢复文件或对比历史状态时用临时副本或副本目录；未经授权不得覆盖用户修改，也不删除未确认归属的文件；用户明确要求的恢复操作按该请求执行。
- 项目未提供并发写锁时使用项目现有分支、工作树或协作机制；并行写同一文件先约定归属与整合方式。

## 版本与交付

- 每个结论绑定候选版本：修改位置、产物版本、被审版本与运行版本分别列明；无法对应时说明。
- **完成层级**（见 [证据与复用](evidence.md)）：研发完成、发布就绪、上线验证；报告写清本次达到哪一级、还缺什么。
- 交付物清单：本次修改与交付物（代码、文档、配置、脚本、数据变更）逐项列出，并与候选版本绑定；不由生成产物反推交付范围。
- 实际部署与不可逆操作使用宿主/项目实际授权，并说明候选版本、目标环境与授权前提；只要求准备时止于准备。
- 结果未知先调查实际状态与回执，再决定下一动作，不盲目重放。

## Git 与交付动作

- 先确认版本控制状态：是否为仓库、当前分支、已有修改（含未提交与已暂存）与本次 diff 范围。不是仓库或未启用版本控制时按项目现有机制记录候选，**不自动初始化仓库**，也不为此改造工作区。
- 本次变更范围以实际 diff 为准（文件与行段），不以生成产物或暂存区反推；diff 与候选版本的对应关系写入交付说明。
- 暂存、提交、推送与 PR／合并**分别按请求执行**，各自需要明确授权：要求其中一项不顺带其余项——未要求推送时不推送，未要求 PR 时不建 PR。
- 报告写清实际完成到哪一步（已改／已暂存／已提交／已推送／已建 PR），不把上一步写成已完成。
