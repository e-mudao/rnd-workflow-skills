# 实现与根因修复

执行前读取 [协作约定](references/workflow.md)，确定本次范围及阶段返回方式。按需读取 [执行与日志](references/execution.md)、[证据与复用](references/evidence.md)、[影响范围与检查选择](references/impact.md)、[环境与版本](references/environment-version.md)。

读取当前要求、相关代码、已有的适用计划/验收及适用专项；已有计划按计划实施，明确且低风险的任务可直接依据用户请求与相关现有事实实施，不因缺少计划文档阻断或补造计划。负责代码、测试、实验执行与真实证据；实施前核对已确认范围及待答检查点，不把建议下一批当授权。

## 方法

1. 按实际依赖顺序实施；已有计划安排关键反例探针时先执行。记录 RED 的实际类别：缺类型/函数的编译 RED 可用于建立新接口；它不证明捕获旧错误。新增行为先取得可执行断言的失败；已有缺陷尽可能在旧实现运行回归，说明哪个行为断言失败，再对修复版同测通过。旧环境不可恢复或故障无法稳定复现时，记录原因、可获得的日志/故障样本/最小复现及证明范围，核对修复后行为并保留不确定性；按影响与恢复成本推进可验证工作，关键正确性仍无法判断时暂停依赖工作，不把修复后通过称为捕获了旧错误。外部系统保留最小真实复现，将可提取规则纳入测试，不可自动化部分保留真机复验缺口。测试实际行为，不以 mock 或测试数量证明覆盖。
2. 调试按四阶段进行：复现与根因定位 → 对照有效例找差异 → 单一假设做最小试验 → 用失败回归和修复验证。多次修复无效时重新检查假设和架构。
3. 准备人工验收时，依协作约定绑定实际运行候选与轮次；有待答人工验收时，新构建可能覆盖被测候选就先保存并核对可恢复产物，新构建与运行版本分列，不擅自替换用户正在验收的实例。使用项目现有测试、构建和检查命令，保留真实 cwd、命令、退出码和输出。相关检查通过后核对必要门禁，已有充分证明时停止重复测试。
4. 实现与计划接口不符时记录偏差并交 plan；验收不可判定交 spec。保持修改范围，不重构无关部分，不代改验收消除失败。

实验按现行方法/样本/配置执行，保存原始数据引用、输出及运行事实；记录自身错误由本角色修正，受影响计算实际重跑并保留历史失败。方法/样本缺陷返回 plan，分析结论交 discover，不能由 build 改方法、标准或分析来获得正面结果；仅调研请求不新增产品实现。

## 核验与返回

交付具体修改、检查结果、未解决项和偏差，再交 reviewer。非零退出保留为失败，中断和缺项如实说明；实施缺陷或计划内测试遗漏由本角色修复（RTN-3）。

完整开发目标内，返回修改/证据位置、实际结果、偏差及下一动作给 lead，接续审查/具体问题复验；直接请求实现时按该范围交付。

请求明显超出本角色范围时，保留当前目标、授权、停止点和已知结果，转入 `rnd-lead` 接续；已由 lead 分派的工作按既有阶段返回约定接续。转入前按协作约定核对目标技能可用性。同一 Agent 切换职责，无需用户重新调用。

改编 Superpowers 执行、TDD 和 systematic-debugging，见 [固定来源](references/methods.md)。
