# 当前状态与问题闭环

需要交接、跨阶段恢复，或需更新既有状态与问题表时使用本参考。范围与授权沿用 [协作约定](workflow.md)。

需要交接或跨阶段恢复时，先确定现有 README/任务文档中的唯一当前摘要及问题表位置，按以下动作维护，不新建并行状态入口：

1. **原位更新当前段。** 记录实际项目根与目标、权威规格/计划链接、授权与停止点、当前源码/新构建/实际运行候选、待答轮次、未关闭问题引用及下一动作。不同版本分别列明；未知运行身份保留未知。问题状态在选定的现有问题表原位更新，其他位置引用该表。
2. **处理过时入口。** 核对本次涉及文档的首页/当前段。被取代的“当前、下一步、待答、未关闭”段改为指向唯一当前摘要的引用，或在该段之前标明“历史（日期/候选，已被何处取代）”；仅在文末追加更正不能消除顶部歧义。历史发现和失败保留，现行修复交接撤销；正文判断由责任作者修正。
3. **沿用真实确认。** 摘要记录待答建议的版本/范围、实际确认的版本/范围及答复依据（消息位置或忠实原意），包括部分确认与连续授权。收到答复后在原待答位置更新状态并引用依据。下一动作不是批准；已确认不重问，待答不推定通过。
4. **在批次、需求变化、反馈归属或问题关闭后回读。** 从唯一入口检查能否判断：正在验哪个候选、等谁对什么动作答复、哪些问题仍开放、下一步是否获准。再核对相关文档入口与实际产物；有冲突先查版本/记录，未能确定则标出缺口。写入后读取落盘内容，不能只依据拟写文字宣称更新完成。

报问题或安排修复前，重读当前源、命令和被审版本；发现 ID 绑定报告/版本。完整目标内：确认发现 → 对应作者修复 → 具体复验 → 原位更新问题表与当前摘要。关闭注明已覆盖的候选/场景，其他范围不随之通过；重开须有当前反例。只审查请求止于发现及建议，不直接改被审内容。
